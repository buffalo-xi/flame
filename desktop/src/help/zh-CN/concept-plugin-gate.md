# 插件与能力的两层开关

平台管理台的「插件与能力」里有两组东西，**缺省方向正好相反**。把这一条记住，后面都是它的推论。

## 一句话区别

- **插件**：磁盘上有这个实现就能用，平台只在需要时**对某一家停用**。缺省 = 允许。
- **能力**（执行 / 常驻会话 / 代码片段 / 浏览器 / 出网）：等于「这个租户能自己跑代码、能出网」，平台必须**逐个开通**。缺省 = 拒绝。

## 三层，从外到内

| 层 | 在哪设 | 说明 |
|---|---|---|
| ① 全局闸 | 右侧详情顶部「全局停用（急停）」/「全局硬闸」 | 缺省放行。一旦拉下，所有租户立即失效，**压过**各租户自己的设置 |
| ② 平台对某一家 | 表格里每行的开关，改完点该行「保存」 | 插件：打开 = 只停用这一家；能力：打开 = 只对这家开通 |
| ③ 租户自己 | 租户控制台 → 工具 | 插件要租户自己启用并选实现；能力还要租户把它授给具体智能体 |

## 什么情况下真的可用

任意一层不满足都不行：全局闸没拦、平台没对这家关掉（或者已经开通）、租户自己启用了、能力还被授给了具体智能体。

被挡下时工具目录里会置灰并给出原因，**执行层直接拒绝**——不是靠提示词劝住模型。

## 三种状态怎么读

| 看到 | 意思 |
|---|---|
| 未设置（缺省允许 / 缺省未开通） | 这一家没有单独设置，按缺省走 |
| 单独设置 | 这一家有一条自己的记录 |
| 全局急停中 | 闸在拦。各租户的原始设置**仍然保留**，解除停用或解除拦截后按原设置恢复 |

## 出网不是按域名管的

「出网」是跨通道的出口策略，管的是 exec / 会话 / 技能脚本能不能访问外网，不是防火墙。

两个前提：exec 或 shell 至少开通一个（两个都关时开关是灰的，后端也会挡），并且它自己已经开通。关掉之后命令照样在沙箱里跑，只是访问不了外网。

**要按域名管控出网，走工作流的 http 节点**，别指望这个开关。

## 成本落在平台侧

浏览器是常驻 Chromium，执行族会留下常驻进程 —— 这些资源占的是平台，不是租户。所以这类能力缺省拒绝，由平台逐个开通。

## 容易搞反的地方

- **插件的开关是反的**：打开 = 停用这一家，不是允许。开关上写着「停用 / 放行」就是为了提醒这一点；能力的开关是正的（打开 = 开通）。
- **急停不清授权**：它只压一层，解除后回到各家原来的设置。
- **「租户自己启用了」不等于能用**：对插件成立（平台没设置时），对能力不成立——能力缺省拒绝，平台不开通，租户那边连开关都是灰的。
