# 「工作流」这一页与编辑器

## 列表页

顶部按状态筛选（全部 / 正常 / 废弃）、搜索名称与描述，右边「导入」和「新增工作流」。卡片上显示名称、状态、版本（`v3` 或「未发布」）、协议（mcp / rpc 或「未设置端点」）、最后更新人。

鼠标悬停浮出五个动作：切回正常、废弃、端点、导出为资产包、删除。**废弃会同时收回该工作流全部端点的对外**，部署里还在调的调用方会立刻失败。**删除会连同它的运行记录一起清掉**（运行历史页不再有它），未对外的端点一并删除；仍有对外端点时先「收回对外」。

一个工作流都没有时，列表位置会说明工作流能做什么，并给一个「创建工作流」入口，不用去顶部找按钮。两条路：跟 main 智能体对话让它把流程搭出来（例如「帮我做个工作流——读昨天的订单，按地区算总额，再整理成一段话输出」），或者点这个按钮手工画。按状态筛选或搜索没命中时只显示一行提示。

## 编辑器分成三块

左侧竖向工具条（加节点、加注释、变量面板入口）、中间画布、右侧浮层面板（节点属性、变量、运行）。面板可以拖宽，也可以关掉。

**加节点有两条路**：工具条「+」→ 选类型 → 再点画布落位；或者点已有节点上的「+」→ 选类型，新节点自动建在右边并连线。注释不占节点名额。

「+」面板分「节点」和「工具」两个 tab。节点 tab 按类型建空节点；工具 tab 列的是**已经连好的东西**——本租户暴露的 RPC 端点、MCP / RPC 连接下的工具。点一条就直接生成节点：连接和工具都选好，参数还会按接口声明的入参 schema 生成一份样本（有必填项就只放必填项，值只是类型占位），把样本里的空值换成真实取值就能跑。节点落位后会自动选中、直接打开属性面板，样本就在参数框里。在属性面板里换工具，参数框会直接换成新工具的入参结构（RPC 节点改用端点时同理），原来写进去的取值会被覆盖——要留的先复制出来；接口没有声明入参时给的是空的 `{}`。工具下拉右侧的「?」按当前选中的工具打开详情：描述、每个入参的类型与是否必填、说明和可选值，以及原始 schema；没选工具时它是灰的。RPC 节点选「本地端点」时，端点下拉旁同样有一个「?」，打开的是端点详情：目标类型、对外状态，以及同一张入参表。目录里的连接默认收起，展开才去拉它的工具清单；指向当前流程自己的端点不会出现（自己调自己必然失败）。都空的时候，先去「设置 → 工具」加连接，或者把流程暴露为端点。

## ESC 与离开编辑器

ESC 一次退一层：先收起右键菜单和下拉，再关右侧面板（属性、变量、试运行）与版本面板，都没有了才退出编辑器回到列表。正在改头部名称时按 ESC 只取消这次改名，不离开页面。

**有未保存改动时退出会先确认**（返回按钮同样会问）—— 没保存的修改离开后就没了，编辑器不会替你保存。

## 连线的硬规矩

source / target handle 不能同类型互连，不能自连、不能成环、不能跨父容器；而且**一个出口只保留一条出边、一个入口只保留一条入边** —— 重连是覆盖，不是新增。终态节点（`exit` / `break` / `continue` / `return` / 主动报错）只有入口、没有出口：主动报错永远以失败结束，接在它后面的节点一次都跑不到。

## 变量的三类来源

| 来源 | 谁维护 | 说明 |
|---|---|---|
| 流程变量 | 本工作流 | 编辑器里可读写 |
| 环境变量 | 本工作流 | 随工作流走 |
| 全局变量 | 租户级，编辑器里**只读** | 维护在「设置 → 全局变量」；地址、账号、密钥建议放这里 |

在节点的「输入变量」里引用前，要先把来源选对，模板（`{{.input.x}}` / `{{.local.x}}` / `{{.output.x}}`）才认。

## 试运行

点「运行」会**先自动保存**再跑。结果看三处：右侧运行面板（本次运行 / 历史运行）、变量面板的「执行结果」子页、画布上节点的调试高亮（执行中 / 已运行 / 跳过 / 出错 / 断点）。

节点失败时，「错误」一栏是节点自己的错误码与提示；如果它在「错误处理」里配的处理器或收尾脚本**自己**失败了，执行结果里会另起「处理器错误」/「收尾错误」两行——节点仍按原来的错误失败，错误码不会被改写。

## 并发执行

一个 `process` / `loop` 的 body 就是一次并发作用域。把它的**直接子节点**在属性面板里勾上「在父节点中并发执行」，这个节点就成了成员：body 派发它之后继续沿链走，body 结束时统一收口。只有会等的步骤有这个勾选项：入口、`break` / `continue` / `return` / `exit`、注释 / 布局节点、`result` / `progress` 以及 `assign` / `memory` / 主动报错都没有——控制流待在链上（`exit` 写在成员自己的 body 里，照样结束整个运行），结果与进度按调用顺序追加到本次运行上，勾成成员会按调度顺序插队，而 `assign` / `memory` 本身不等待，占一个并发位没有任何收益。

成员的身份只看节点数据里的 `data.concurrent`（勾选框与工具参数都写它）。画布上被勾成成员的节点，标题旁有一个蓝色并发图标，悬停显示「在父节点中并发执行」——图标只是提示，改它仍然在属性面板里。

- 宿主在属性面板的「并发作用域」里设上限与汇合方式：新建的流程段默认 8；上限开关关掉表示作者不设上限，但运行时仍按租户天花板（设置 → 工作流运行参数 → 最大并发数，兜底 16）排队，超出的成员等空位而不会失败。`collect`（默认）等所有成员各自跑完；`drain` 表示第一个成员失败后不再启动新成员（排队成员与后续链节点记 `skipped`）。
- `abort` 在 `drain` 之上再取消正在运行的成员（记 `cancelled`，原因 `aborted by scope`）：宿主已经失败时，不再为一个没人读的结果继续烧 LLM / 沙盒调用。body 自己那条链不会被中断，只在下一个节点边界停下。
- 「并发作用域」里还能设作用域超时（秒）：到点后取消仍在跑的成员，宿主记 `failed` + `err_code: timeout`，消息里列出每个成员当时的状态，快照标记 `abandoned`。它和你给单个节点设的超时是两个层级的东西——节点超时只终止那个节点，作用域超时终止这一次 body 的并发。
- 成员失败会让整个运行失败，不用等谁去读它的结果。
- 想把「并发失败」变成可继续的：在**宿主自己的**「错误处理」里配「跳过」「处理器」或「收尾」——跳过让主链越过这一段（成员记录都保留，跳过之后依然能看到谁失败），处理器可以改写错误码 / 提示，或返回 skip 把它也变成跳过，收尾（post）用 `set_outputs` 给宿主写兜底值（例如 `ok = false`）——处理器写不了 outputs。宿主没有「重试」：重跑整段 body 会把每个成员的副作用重复一遍，那不是重试失败的那个成员。成员自己的「错误处理」先执行，多数情况在那里就够了。
- 成员之间不能互相读结果，链上节点也不能读成员：要让 A 的结果给 B 用，就放两个宿主，前一个的 `outputs` 给后一个读。
- 顶层、`function` 的 body、`branch` 的车道都不是作用域，在那里勾选会在保存时被拦下。

## 保存前的检查

点「保存」（以及试运行前的那次自动保存）会先把画布内容交给后端做一次静态检查，**不执行任何东西**：配置块结构、容器入口、跨容器连线、悬空的
`source_ref` / `call.target`、分支条件没有出边、`loop each` 的数据源没在入参里声明、节点不可达，节点不支持（或永远不会命中）的
`on_error` 动作 / 错误码、同一个错误码同时写在「跳过」和「处理器」里（跳过先匹配，处理器永远不会执行），以及「配了跳过却没有兜底值、下游还在读它的 outputs」——跳过时下游拿到的是空值，和「真的返回了空」分不出来，
所以这条会以提醒的形式报出来。

结果按「错误 / 提醒」列出，每条都定位到节点与配置项：

- **错误**：按现在的写法跑不起来（比如 code 没有脚本、分支没有子节点、脚本语言沙箱不支持、break 不在任何循环里）；
- **提醒**：能跑，但很可能不是你要的结果（比如 code 没声明 outputs、某条兜底规则永远不会命中、assign 里没有写任何赋值、分支子节点没写条件脚本）。

检查跟着编辑自动重跑（停下改动约 1 秒后），不用先点保存：有问题的节点在卡片标题那一行多出一个小圆标 —— 红色是有错误、琥珀色是只有提醒，悬停列出这条的文案与配置项，点一下定位到该节点。保存前弹窗里的清单也一样：点任意一条就跳到那个节点并打开它的设置（这次保存会取消）。

检查只是提前告知，**不挡保存** —— 画布是草稿，画到一半很正常；真正拦写的只有后端那几条硬规则（标签重复、节点数超配额）。同一份清单在同一个工作流里点过
「仍然保存」后不再重复弹窗：你已经看过并确认过，只有清单变了（修掉一条、又出现新的一条）才会再提示。Agent 在对话里用 `validate_flow`
拿到的是同一份结果，所以「画布说没问题、跑起来却失败」不会因为两套规则而出现。

## 保存 ≠ 发布 ≠ 生效

- **保存**：只写草稿。
- **发布当前内容**：冻结当前已保存内容为新版本，正式调用立刻跑这一版；有未保存改动会被拦。
- **切到线上**：只换「线上跑哪一版」，画布草稿一动不动。
- **载入画布**：把该版本写回草稿，线上仍是原来那版，要再发布才生效。想丢掉草稿回到线上那份，也用它。
- **取消发布**：把当前版本从线上摘下来，只清「线上是哪一版」这个指针；版本历史、画布草稿、端点都不动，正式调用立刻报「未发布」，之后可以再发布。**有发布版本时不能直接删工作流**，先取消发布再删（删除不该顺带停服）。

头部版本按钮有三种状态：「未发布」（还没发布过，线上不可调用）、「v3 · 有改动」（线上是 v3，草稿比它新）、「v3」。

## 端点

编辑器头部「端点」按钮就地管理这个工作流的入口，不用跳去端点页。工作流没保存前点它会提示先保存。端点参数不能手写，恒等于开始节点声明的入参；RPC 端点由流程托管，不能单独删。工作流没发布过正式版本时不能对外开放，先发布再开。

**有对外端点时保存会二次确认**：改名会连带改变对外工具名（`local__<name>`），外部接入方要同步改。
