# 「租户管理」这一页

左栏是租户卡片，右栏是选中租户的六张折叠卡。**每张卡有自己的保存按钮**，没有全局保存。

## 左栏

卡片三行：显示名 + 状态、schema · 负责人、三格用量（用量 / 上限）。顶部可以按 schema 或显示名搜索（**回车才触发**）、按状态筛选，底部是后端分页。

没设负责人的租户显示「管理员代管」。

## 六张卡

| 卡 | 改什么 |
|---|---|
| 租户资料 | 显示名、负责人、备注 |
| 配额 | 五项配额的**本租户原始值** |
| 插件 | 平台对本租户的插件停用设置 |
| 能力授权 | 执行 / 会话 / 代码 / 浏览器 / 出网 是否对本租户开通 |
| 工作流运行参数 | 超时、递归深度这些安全阀的租户值；系统级只读对照 |
| 智能体运行参数 | 同上，多一列「实际生效」 |

**插件卡与能力卡的方向相反**：插件缺省允许，打开开关 = 停用这一家；能力缺省拒绝，打开开关 = 开通这一家。要撤销单独设置，插件点「恢复缺省（允许）」，能力点「恢复未开通」。

## 新建租户

schema 是自动探索出来的（从 t0 起逐个 +1 取第一个没被占用的），不可编辑，可以「重新探索」。登录名固定 `primary`，初始密码预填但可改、必填。套餐只作标记。

开通会在**单个事务**里做完：建 schema、按模板建表、创建首个租户管理员、写注册表行。

两种常见失败：

- **schema 被抢占**：提示已被占用并自动重新探索，弹窗不关，确认新值后再点一次「开通」。
- 前置校验没过：schema 还没探索出来，或初始密码为空。

## 转移负责人

在「租户资料」卡里改负责人下拉（只列角色为「用户」且状态正常的账号）。保存时会二次确认，因为**这等于转移归属**：新负责人立刻在自己的「我的租户」里看到并管理它，原负责人失去入口。

## 停用 / 启用 / 删除

停用后该租户无法登录控制台，MCP / RPC 调用也会被拒，立即生效；启用不做别的动作，只是恢复。

删除要求**先停用**（正常状态下删除按钮是灰的，这是前置条件，不是权限问题）。删除会清空该租户的 schema 与文件目录，不可恢复。

## 配额与运行参数怎么算

- 输入框里填的是**本租户原始值**：留空 = 未设置（回退系统级），`-1` = 不限制。
- **生效值 = min(本租户值, 系统顶)**，由后端算好回带，前端不重算。
- 管理员填了高于系统顶的值会照存但被截断生效，卡底有黄字提示；租户自己改超系统顶是直接拒绝。
- 智能体那组没有 `-1`（都是安全阀，必须 ≥ 1）；工作流那组支持 `-1`。
- 会话空间按 MiB 填。

## 备注会同步给租户

备注不是内部字段：租户在「我的租户」里能看到原文。写之前当它会被对方读到。
