# 「工具」这一页怎么看

三个 tab，三个计数各算各的：**工具目录**不含插件、也不含自定义工具，所以三个数字加起来才是全部。

## 工具目录的四段

| 段 | 是什么 | 能做什么 |
|---|---|---|
| 工具组 | 你自己建的集合 | 新建 / 编辑 / 删除；成员只能是单个工具或天然组，不能嵌套 |
| 内置工具 | 代码里带的，只读 | 详情、看谁在用 |
| 远程连接 | 我们连出去的 MCP / RPC | 刷新清单、看可用状态、引用 |
| 本地工作流 | 本租户的 rpc 端点 | 看它是「对外开放」还是「仅内部」，跳端点页 |

## 这一页不能授权

授权在**智能体 → 设置 → 工具配置**里做：左侧「工具授权」分「必须导入 / 可使用 / 拒绝」三区，改完回配置区点「保存」才生效。

工具页只回答「我们有什么工具、它现在能不能用」，不回答「哪个智能体能用」。

## 「不可用」有五种原因

平台未开通、平台已停用、插件未启用、连接未启用、端点未对外开放。工具照样列出来，只是置灰，点「详情」能看到具体原因。

**平台策略优先**：租户这边的授权、甚至「不限制工具」开关，都盖不过平台未开通或平台停用。

## 插件 tab

右上角开关只提交「启用 / 未启用」，不动配置。选实现在「配置」侧栏：

- **主实现**：模型只看得到这一个。
- **兜底链**：主实现失败时按顺序重试。配置类错误（比如缺 key）不降级。
- 「试一次」用当前配置真调一次。

被平台停用时开关是灰的，卡片下方有黄条说明是全局停用还是对本租户停用。

## 自定义工具 tab

实现方式是**脚本**（python / js / lua / sh），不是 HTTP。顺序是：新建 → 保存（保存时才创建 `tools/<name>/` 目录）→ 在目录编辑器里写代码 → 试跑 → 发布版本。

注意：试跑只跑**已保存**的代码，表单或文件有未保存改动时按钮是灰的；「允许出网」还需要平台开通出网能力。

键盘上：目录编辑器里按 ESC 退出回工具列表，配置抽屉开着时 ESC 先收起抽屉；两种情况有未保存的配置或文件都会先确认。

## 两个方向别搞反

- **远程连接**：我们连出去，用别人的工具。
- **本地工作流**：我们把自己的 rpc 端点暴露给别人，对外开放的开关在「端点」页，不在这里。
