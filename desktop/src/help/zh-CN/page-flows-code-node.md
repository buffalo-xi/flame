# 代码节点：返回值怎么给

代码节点不靠「打印」把结果交给流程，而是把**变量名和值**一起交出去。所以每种语言的代码都必须回答一个问题：返回值放在哪里。

## 三种语言的写法不一样

| 语言 | 怎么返回 | 为什么 |
|---|---|---|
| Lua | 顶层 `return` 一个表 | 脚本整体是一个函数块，第一个返回值就是结果 |
| Python | 给 `__return__` 赋值 | 脚本用 `exec` 执行，`exec` 没有返回值，引擎读 `__return__` 这个变量 |
| JavaScript | 直接 `return` 一个对象 | 脚本被包进一个 async 函数，`return` 就是结果 |

在 Python 里写 `return` 会立刻语法报错（`'return' outside function`），这是最常见的第一个坑。

代码节点只列沙箱支持的脚本语言（lua / python / js）；`template` 是纯 Go 渲染，只出现在「结果」「进度」两个节点里。

## 三条硬规则

1. **返回的是一个「变量名 → 值」的对象。** 键名必须是节点里声明过的名字：输出变量、写目标、局部变量三者之一。返回没声明的名字会失败，报 `undeclared variable`。
2. **值必须能转成 JSON。** 字符串、数字、布尔、null、数组、对象都可以；自定义类、函数、集合不行。
3. **`print` / `log` 不是返回。** 两者都被改到 stderr，只会出现在节点日志里（运行详情中的 `script output:`），不写任何变量。

## 常见错法

- 照抄 Lua 写 `return {...}`：Python 直接语法报错。
- 写了 `def main(): return {...}`，既没调用也没赋给 `__return__`：节点成功，输出全空。
- 在函数里赋值 `__return__` 却没有 `global __return__`：赋的是局部变量，引擎读不到。
- 返回的东西不是对象而是字符串或数字：报 `unexpected return type`。
- 期待 `print(...)` 变成返回值：它只进日志。

## 「没有返回」也算成功

`__return__` 保持默认（`None`）时，节点不报错，只是什么都不写。所以「节点成功、下游变量是空的」几乎总是返回语句没执行到——尤其是它写在 `if` 分支里的时候。

排错看运行详情里的 `script stderr:`：Python 的 traceback 会原样贴在那里，行号就是你编辑器里的行号。
