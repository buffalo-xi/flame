# 「端点」这一页

端点是把智能体或工作流**暴露成外部可调用的入口**。这一页就是那批入口的清单。

## 两种协议

| 协议 | 地址 | 参数 |
|---|---|---|
| MCP | `/service/mcp/<schema>` | 智能体不声明入参，外部按自由 JSON 传 |
| RPC | `/service/rpc/<schema>` | 恒等于工作流开始节点声明的入参 |

同一个实体每种协议只能有一个端点，**端点名就是实体名**，不可改。

## 参数不能手写

RPC 端点的参数固定来自开始节点：改流程的开始节点入参，端点跟着变。这是刻意的——避免「端点签名」和「实际实现」两套说法。

## 对外开放 / 收回对外

- **对外开放**：带凭证的外部调用可以进来了。
- **收回对外**：立即停止外部调用，端点记录、入参定义、绑定全部还在，再开就恢复。

对外开放要求目标**正式发布过版本**：智能体 / 工作流从未发布过时，开关会被拒绝并提示先发布。理由是外部调用跑的就是线上版本，没有版本等于开了一个每次调用都报「尚未发布」的入口。超级智能体是例外——它始终按草稿运行，所以不要求发布。

「收回对外」不是删除，也不是「仅内部可见」——它管的是**能不能被调**。

## 删除与废弃

对外开放中的端点不能删，要先收回。智能体或工作流被**废弃**时，它会自动收回自己的全部端点——部署里还在调的调用方会立刻失败。

RPC 端点由流程托管，不能单独删。

## 凭证范围决定「谁能调」

新建的服务凭证默认「已限制端点范围且目标为空」，**不点配置勾上目标，这把 Key 调不到任何端点**。给外部凭证授权超级智能体端点，等于把租户管理能力交出去。

## 哪些端点能进工具授权

只有**工作流的 RPC 端点**可以进工具授权体系（引用名 `local:rpc:<name>`）。MCP 端点与智能体端点只对外调用，不进工具目录。

## 本页自带的两个入口

标题旁的 `?` 讲术语（什么是端点、怎么创建、怎么调用），「使用说明」抽屉按所选行的协议和入参**生成可复制的 curl 与 MCP 配置**。这两处是这一页独有的，所以没有再挂页面级帮助。
