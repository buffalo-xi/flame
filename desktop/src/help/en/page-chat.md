# The Chat screen

## The session list on the left

Create, search, switch, delete — four things. **No rename, no pinning.** Session titles are generated by the
backend; an untitled one shows as "New session".

The session count is per account and **shared across agents**. At the limit, creating another is rejected.
Deleting asks for confirmation and is final.

## The agent dropdown at the top

Searchable, with a "super agent" badge. A session belongs to one agent: **switching agents clears the current
session, messages and attachments**, then loads that agent's sessions and opens the most recent one. On
entry the app restores "the agent with the latest conversation", falling back to main.

## The message area and tool call cards

A tool call is a card: status icon + tool name + duration. **Click the title row to expand** and see the
arguments and the result (both truncated to 2000 bytes by the backend). A failed call shows a red cross.

A `call_agent` sub-agent's steps are nested inside the parent card, with its own thinking blocks and tool
cards. Thinking blocks collapse.

## The input area

Enter sends, Shift+Enter breaks the line, and Enter during IME composition does not send. "+" attaches any
file type, including images — **≤ 20 MB per file, ≤ 5 files per message**.

The slash-command panel lists skills marked "user-callable": ↑↓ to move, Tab to complete, Enter to confirm,
Esc to close.

## Stop is not undo

While running, the send button turns into a red stop button, which **drops the connection** rather than
sending a stop request (on a multi-instance deployment that request would land on the wrong instance). Tool
calls that already ran, and files already written to the workspace, stay.

After a stop, a line "[stopped]" is appended to the assistant's message; reloading from history shows a
different label instead — "this run was stopped".

## Only your own messages can be copied or edited

User messages get "copy" and "edit" on hover; **assistant replies have neither copy nor regenerate**. "Edit"
discards that message and everything after it, then resends the edited text.

A single message cannot be deleted; only a whole session can.

## Features that do not exist

There is no "clear context" — start a new chat if you want a clean slate; the old session stays in the list.
"Close session" (the × in the toolbar) only hides the pane, it does not delete anything. History also does
not keep attachments: they are visible only in the turn that carried them.
