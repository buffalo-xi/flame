# Excel 报表处理

## 用途

把工作区里的一份表格文件按给定规则处理成一份**新文件**（清洗 / 筛选 / 汇总 /
加列 / 拆表），产物写进工作区的 `out/` 子目录，输入文件保持不动。

## 何时使用

出现这些意图时读它：

- 用户给了一份 `.xlsx` / `.xls` / `.csv`，要求「处理 / 汇总 / 清洗 / 合并 / 拆表 / 加一列 / 出报表」
- 需要多步、有规则的批量变换（不是只想看一眼某个单元格）
- 上一次跑失败了，要改脚本重跑

**不要**读它：只想知道表格里有什么（列名、行数、某格的值）—— 直接跑一句 `python -c`
更快，不必走整套流程。

## 怎么做

### 0. 先确认环境，不要靠猜

```
python /skill/scripts/probe.py
```

它打印 python 版本、可用库、挂载点、`sys.path[0]`。

**缺库时不要 pip install** —— 沙箱断网（nsjail `disable_network` / docker `--network none`），
装了必然失败，只会白烧修复轮数。缺什么就如实告诉用户，由管理员改沙箱镜像。

### 1. 确认输入

输入文件在工作区根（沙箱内即 `/workspace`，也是 exec 的 cwd）。先 `list_files(dir="")`
看清文件名与大小。**就地读它**，不复制、不移动、不改名。

### 2. 写脚本

入口固定 `scripts/main.py`（技能目录内）。它已是可运行的参考实现（按金额列筛选 +
汇总 + 自检），改 `process()` 即可。

**路径一律相对当前工作目录，不要写死 `/workspace`。** exec 会把 cwd 设成工作区根，
而 `mode: none`（本机调试）下只有 argv 与 cwd 会被翻译回宿主路径，脚本正文里的绝对
路径不会被翻译 —— 写死会在本机直接失效。

需要拆模块时：

- 附属模块放 `scripts/lib/`，用**绝对 import**：`from lib.excel import read_rows`
- **禁止** relative import —— 脚本是直接执行的、不是包，`from . import x` 会报
  `ImportError: attempted relative import with no known parent package`
  （`sys.path[0]` 是脚本所在目录 `scripts/`，绝对 import 正好落在这里）
- **默认单文件**。只有超过约 150-200 行、或出现两个真正独立的关注点时才拆 ——
  每多一个文件就多一次写入、少一轮修复预算，而整个循环只有 20 轮

### 3. 五条硬约定（这个技能存在的意义，别省）

1. **输入只读** —— 只读工作区里的输入文件，绝不写回。改坏原文件不可逆。
2. **产物只写 `out/`** —— 文件名固定可预测。工作区根下的 `.py` 是草稿不是产物。
3. **失败带信息** —— `sys.exit(1)` 退非 0，把**可读原因**写 stderr（缺哪列、哪一行、
   什么类型不对），不要只抛裸异常堆栈。
4. **幂等** —— 同一输入重跑结果一致，允许覆盖 `out/` 下的旧文件。
5. **写完立刻回读自检** —— 校验行数 / 列名 / 关键单元格非空，不通过就退非 0。
   让问题在脚本内暴露，而不是等用户打开文件才发现。

### 4. 跑

```
run_skill_script(skill="xlsx-report", args=["--input", "in.xlsx", "--min-amount", "1000"])
```

`run_skill_script` 会把技能目录**只读**挂到 `/skill`、工作区挂到 `/workspace`（同时是 cwd）后执行。
脚本路径**必须**在该技能目录内 —— 工具会拒绝任意路径（那是 `exec` 的事）。

### 5. 失败怎么修

- 先**完整读一遍 stderr**，再动手改，不要凭印象改
- 只改导致失败的那一处，不要顺手重构
- **最多 3 轮**。第 3 轮还不过就停下，把「最后一次 stderr + 当前脚本全文 +
  输入文件的真实结构（列名 / 行数）」一并交给用户说明卡点，不要继续空转
- 重跑是**整段重跑**（所以必须幂等），不支持补跑半截

## 注意事项

- **大文件会被资源上限打断**：内存 512MB、单文件 64MB；超时取「nexus 工具超时（默认 60s）」与「sandboxd exec 上限 120s」的较小者，实际按 60s 规划。
  输入超过约 20MB 或几十万行时改用流式：`load_workbook(read_only=True)`、
  `pandas.read_excel(..., chunksize=N)`。
- **`openpyxl` 不计算公式**：`load_workbook(p)` 读到的是公式字符串（如 `=A1+B1`）；
  `load_workbook(p, data_only=True)` 读到的是**上次 Excel 计算后缓存的值** ——
  如果这份文件从没被 Excel 打开过，缓存是空的，读到 `None`。遇到公式列先跟用户确认。
- **`.xls`（老格式）要 `xlrd`**，与 `openpyxl` 不是一套；先跑 `probe.py` 确认。
- **列名不要靠位置猜**：按列名取值，取不到就明确报「缺少列：金额」——
  位置索引在不同文件之间会漂移。
- **不要用 `import` 报错来试探环境**，先跑 `probe.py`。
